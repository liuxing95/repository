## 重点与修复

- 正确性、API：固定基线摘要绑定、原始尝试不可覆盖，已存在叶子项不允许从新分母删掉；当前／历史范围分别呈现。自报和模型评分不计入验收权重。
- 可靠性、并发：容量观察必须完整、新鲜且 ID 唯一，SQLite 事务统一预留。未知结果、重启及重复点击不重发，明确最终未创建才释放；不把任务意图当已创建事实。
- 权限：所有 HTTP 入口鉴权，写操作绑定当前主端与政策版本；原文每次回读检查，受限尝试和建议不返回旧正文。用户不能提交伪造的程序／模型评价来源。
- 迁移：schema 6 识别及私有备份，旧研究记录保留，新库重开可写；不删除或重建权威账本。
- 界面：文本节点显示用户内容、旧草案响应失效、调用后保留身份；截图核对后将评价 JSON 改成来源、结果、依据及规则的自然表达。

五项审查问题均先加失败用例，再修复：

1. 关闭容量配置再换时区绕开自然日账本；现在直接核对已有意图中的时区。
2. 创建仍在等待回执时，核对可能按暂时缺失提前释放预留；当前请求在途期间不发出这种核对。
3. 多次尝试在同一毫秒登记评价时，按尝试分组排序会选错最新更正；改按评价账本全局登记顺序。
4. 确认目标响应丢失后点击重试生成新操作 ID，可能重复建目标；确认控件持有同一操作身份。人工评价同样保留该次控件的操作身份。

5. 重新读取活动时仍允许编辑旧输入框，响应返回后可能丢掉刚填的评价；所有输入与新建控件在请求期间禁用，恢复完成后再允许填写。

前四项相关 11 项专项通过；末次界面与版本回归 3 项通过。没有为相邻场景增加新的任务引擎、模型调用、自动命令执行或提醒。
