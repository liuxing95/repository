# 整套知识库方案总览

**整理日期：2026-09-21｜性质：对本次讨论与现有文档的归纳，不是新的功能发布或独立研究结论**

## 1. 系统最终服务什么

目标不是在 Obsidian 中加一个聊天框，也不是自动生成大量笔记，而是形成可追溯的循环：

```text
原始材料
  → 资料获取、固定版本、结构解析、覆盖报告
  → 可检索证据和带范围的知识主张
  → 课题研究 / 学习目标
  → 可执行个人任务与日计划
  → 执行、实验、回忆、反馈
  → 复习与知识修订候选
```

输入既包括网页、官方文档集合，也包括代码、发布产物、PDF、文本片段。普通生活待办可以独立存在，不强制关联知识。

## 2. 推荐架构与复用边界

以 [v2.1 设计](../01-当前设计基线/Obsidian-KB-v2.1-Audit-and-Task-Planning-2026-09-21.md)为最新候选，主线为 Obsidian + TaskNotes + Knowledge Bridge 扩展 + TypeScript 本地知识/计划服务。各项目能力的历史依据仍在原调研内，本次没有重新验证候选版本。

| 组成                       | 负责什么                                          | 明确不负责什么                                 |
| -------------------------- | ------------------------------------------------- | ---------------------------------------------- |
| Obsidian                   | 阅读、编辑、导航、笔记与资料呈现                  | 不天然提供来源治理或后台在线服务               |
| TaskNotes 适配             | 用户任务、状态、计时与任务视图                    | 不被当成已验证的自动排程器                     |
| Knowledge Bridge（待开发） | 导入、查询、审核、Today、TaskNotes 观察与受控写入 | 不直接给模型任意文件写权                       |
| TypeScript 服务（待开发）  | 来源、任务/计划账本、检索、编译适配、研究和预算   | 不无限制运行通用 Agent                         |
| 格式 worker                | 代码、复杂 PDF 和其他格式的有界处理               | 不执行导入项目、宏或资料中的指令               |
| 在线提醒执行端（按需）     | 发送已登记、最小化的提醒                          | 不持有全量原始知识库，不假装知道离线未同步状态 |

原调研将 atomicstrata 作为 TypeScript 编译器首个复用验证对象，QMD 等作为检索增强候选，PandaWiki/Quartz 作为可选发布端；这些不是必须一起安装的组件。具体采用需锁版和契约测试。

## 3. 收录规则

统一入口是拖入文件、粘贴网址、选择目录或粘贴片段；用户确认范围和权限，而不是预先把材料转成 Markdown。

**网页：** 保存实际取得的原始内容和规范化正文。需要登录时优先通过用户有权访问的浏览器剪藏；正文不完整要标为节选。

**官方文档集合：** 从机器索引、sitemap、导航和内部链接发现页面，先生成有界清单，再逐页获取。一个入口页不代表整站，集合快照按页保存成功、失败和排除项。

**代码：** 固定实际 commit 或本地文件快照；按路径、符号与行范围建立定位。源码 profile 和发布产物 profile 分开，用户上传 dist 时不能默认排除研究主体；导入不执行安装、构建或测试。

**PDF：** 原件独立保留，按文字、表格、图片和页面记录解析情况。扫描/图表未处理时允许部分可检索，但不得宣称读过全文或推导全量否定结论。

详见 [统一多来源收录方案](../03-资料收录与课题研究/Obsidian-KB-Multi-Source-Ingestion-2026-09-20.md)。

## 4. 准确性依靠哪些机制

保留来源修订、解析产物和软件适用版本三个不同概念。摘要、指代消歧和图片说明是派生字段，不改写原文。

一条技术主张至少带主体、版本/分发、阶段、条件及证据。Vite 示例用于说明：组件实现语言不等于整个产品实现语言；不同阶段、版本和预览路线不能直接合并。其具体事实与形成日期见原专题，不在本总览重新声明为当前事实。

相关性用于找材料；支持、限定、矛盾候选和版本演进用于解释主张。未知范围保留 unknown，向量相似度、链接密度与模型 confidence 不能充当正确性保证。

引用必须回到固定原件或明确的用户陈述；历史 AI 回答不能成为新一份独立外部佐证。原文位置校验是机械门禁，语义是否支持结论仍需独立核查和实际评测。

详见 [版本关联与课题生成](../03-资料收录与课题研究/Obsidian-KB-Ingestion-Relations-and-Research-2026-09-20.md)。

## 5. 输入课题之后的研究过程

```text
明确范围和目标读者
 → 拆解研究问题
 → 按版本/路线/子问题检索
 → 原文、代码、图表证据包
 → 检查覆盖、反证、缺口
 → 按授权补采或说明不足
 → 冻结研究快照
 → 分章节生成
 → 全文主张审核
 → 保存候选，按规则提升为正式知识
```

研究报告不是一次全局 top-k 问答。各章节可以分别取证，但共享顶层预算；补资料需要显式推进快照，不在写到一半时悄悄更换版本。

## 6. 学习与收录如何共存

本次讨论的建议是“自动建立参考库，按课题主动学习”。对确定长期学习的官方文档，自动收录确认范围；阅读端只展开当前单元，深度语义编译按需执行，不把每页都生成一项待办。

学习记录保留解释、回忆尝试、提示、实验与纠错。计时、浏览和模型生成报告都不等于掌握。具体证据与局限见 [自动收录与学习编排讨论整理](../04-自动收录与学习编排/AI-SDK-整站收录与学习编排.md)。

## 7. 任务与计划的关键边界

任务标题、状态、截止和计时由 TaskNotes 任务领域管理；PlanRevision 管被接受的时间安排；普通 Markdown 日计划只是投影。任务多处展示不产生多个互相独立 checkbox。

新增任务后先结构化、验证、读取规划快照，再由有界确定性程序计算。默认提出差异；受限委托后才可自动应用当日未开始、未锁定的弹性块。不因优先级高而修改硬截止、会议、休息或不可拆分时长。

容量不足就显示缺口，不修改任务估计来制造“已经排好”。关联阅读建议不自动成为硬依赖，普通生活任务不强迫附学习证明。

## 8. 实时与提醒并非无条件保证

在线变更通过 TaskNotes 事件、事实重读、服务投影及回执收敛。重复事件合并，断线重连清点；toggle 结果不明时先核对，不能盲重试。

计划接受、Vault 文件更新、日历投影和提醒同步分别记录状态。Obsidian 关闭时不能声称已经写入其任务文件。

本地提醒受电脑与进程状态约束。关机后提醒需要真实在线执行端；只发送已登记规则和允许摘要。动态进度催办需要足够新鲜的任务状态，过期时说明时间或暂停。一个逻辑提醒只有一个发送 authority；取消、恢复与乱序消息依靠代际及账本处理。

## 9. 存储与写入

| 内容                             | 持久位置与责任                              |
| -------------------------------- | ------------------------------------------- |
| 来源原件、结构、图片和代码快照   | 持久对象仓及 manifest，必须备份             |
| 正式知识                         | 页面修订与 provenance；Vault 当前文件可核对 |
| 人工笔记                         | 用户 Markdown，自动化默认只读               |
| TaskNotes 任务                   | 任务文件和其操作接口                        |
| 学习、授权、预算、计划和通知账本 | state.db 等持久数据，不可当缓存删除         |
| 检索索引                         | 可从固定材料和记录重建                      |

知识/来源/计划投影继续使用受控 Writer；TaskNotes 任务通过经验证适配器；日历与提醒各自独立权限。仅拷贝 Vault 不等于备份完整系统。

## 10. 实施与验收结论

先统一 v2.1 合同、四种材料基础收录和任务身份；任务表、只读同步与 Today 可单独交付。计划先建议式，本地提醒先闭环，真实需要时再上线远端提醒与受限自动应用。

旧版 E00—E14 的代码合同、测试思路和模板是参考，不是已经覆盖全部新需求的执行计划；W01—W12 是任务中心工作包，不代表整个多来源研究引擎的全部代码设计。现阶段仍需完成合同迁移、依赖兼容验证和分模块实现。

所有延迟、准确率、费用上限与工时在原方案中均有适用条件。没有真实插件、来源、日历和手机通知测试前，不把文档检查当上线证明。
