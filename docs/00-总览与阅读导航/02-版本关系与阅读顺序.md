# 版本关系与阅读顺序

整理日期：2026-09-21。此文只解释包内现有材料的关系，不将候选设计自动改为已批准规范。

## 1. 各轮交付解决的问题

| 顺序 | 材料                                            | 角色                                                        |
| ---- | ----------------------------------------------- | ----------------------------------------------------------- |
| 1    | 初次完整调研及拆分报告                          | 概念、开源路线、选型依据和早期详细设计                      |
| 2    | v1 技术方案、落地手册、E00—E14 任务、原始实施包 | 小型 MD/TXT 原型与参考合同；范围后来被扩展                  |
| 3    | 资料采集、版本关联与课题生成                    | 主张范围、Vite 案例、版本桶取证、章节证据包                 |
| 4    | 统一多来源收录                                  | 网页、文档集合、代码、PDF、结构与原件定位                   |
| 5    | 自动收录与学习讨论                              | 官方集合自动归档、目标驱动学习、独立学习记录；本次整理成文  |
| 6    | v2 审查草稿                                     | 首次合并任务、学习、计划、提醒与整体问题                    |
| 7    | v2.1 审查和任务中心起步清单                     | 最新设计候选，补充事件重放、计划提交、通知 authority 等问题 |

## 2. 冲突时怎样判断

针对已经被替换的范围、写入域、任务与提醒，以 v2.1 明示条款为最新建议。多格式细节继续读“统一收录”；主张与研究细节继续读“版本关联”；不冲突的安全、证据、存储、预算和恢复细节继承原设计。

| 旧描述                                    | 当前解释                                                                                      |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| 首版只有 Markdown/TXT，PDF 等一律以后再做 | 只是旧原型范围；满足当前需求须覆盖单网页、有限文档集合、固定代码快照和文字 PDF                |
| 所有原件都在 Vault 的 original.md         | 旧文本布局；多格式原件主要在持久对象仓，Vault 保存阅读投影及可选附件                          |
| 所有修改走同一类文本 Writer               | 按域分派：知识/来源/计划投影、TaskNotes 任务、日历各有受控入口                                |
| 一个 active job 即可处理所有事情          | 旧最小原型；当前交互/提醒与长批处理需隔离调度                                                 |
| 任务面板显示 job stage                    | 这是系统作业进度，不等于人的 Todo                                                             |
| 必须文件全部写完才能接受计划              | v2.1 的 PlanRevision 在运行账本接受，文件/日历/通知独立投影回执；来源/Wiki 规则不因此自动改变 |
| 96—150 小时可以覆盖全部                   | 仅是旧范围有条件估算；新需求需重新分项估计                                                    |
| 示例配置可直接开启完整系统                | 配置仅是设计样例；没有随包服务或插件，且自动应用/通知默认关闭                                 |

“最新版”不等于已经完成：v2.1 仍是设计候选，尤其 TaskNotes API 并发保护、真实离线提醒和上游编译适配需要实测。

## 4. 原始文件与重复副本

独立 Markdown 保留原名称；原 ZIP 解开时也保留内部原文件名、相对布局和成员字节，便于核对原检查记录。由此出现有意的重复。不要因为原始包内有旧 README，就跳过本包根 README 的版本说明。

原始 SHA256SUMS 和检查脚本只针对其原目录，不针对整份新合集。包级检查见 [99-交付核验](../99-交付核验/README.md)。
