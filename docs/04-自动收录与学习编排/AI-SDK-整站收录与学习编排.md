# AI SDK 文档整站收录与学习编排：对话整理

**整理日期：2026-09-21｜材料来源：本次对话“自动抓取全部内容还是学到哪里手动录入”的讨论｜不是新一轮网络核验或学习效果实验**

此前这一部分只存在于聊天答复中，本次为完整打包整理为独立文件。下面保留主要问题、建议、实际边界和已出现的来源入口；不将历史网页描述写成经过本次重新确认的当前状态。

## 1. 结论：资料完整和学习主动并不冲突

推荐“自动收录官方文档，按课题逐步学习，手动沉淀理解与验证”。完整参考库服务查找和比较；当前学习单元服务认知负担；个人笔记记录自己的解释、疑问、实验与纠错。

不要求用户逐页复制原文，也不让模型通过全量总结代替人的理解。自动化搬运，不自动化掉思考。

## 2. 一个引言 URL 怎样变成文档集合

讨论入口是 `https://ai-sdk.dev/docs/introduction`。它是发现入口，不代表整个站点，也不能只遍历该路径的子路径而漏掉并列章节。

前次讨论记录了 AI SDK 的机器可读入口：[llms.txt][L01]、[sitemap.md][L02]、[页面 Markdown][L03]、[llms-full.txt][L04]、[文档搜索][L05]。它们在正式开发时须逐项重新验证，不能假定所有站点都提供或遵循同样接口。

| 入口 | 在设计中的角色 | 不意味着什么 |
|---|---|---|
| llms.txt | 了解站点公开的机器访问入口 | 不是全站完整性证明、执行指令或访问授权 |
| sitemap / 导航 | 发现候选页面 | 链接被发现不等于正文已下载 |
| 逐页 Markdown | 方便保存对应页面内容与版本 | 不无条件保证标签页、图表和动态内容全部保留 |
| 拼接全文 | 可选批量来源 | 必须确认范围和页面边界，不每次整包塞给模型 |
| 搜索接口 | 按具体问题找 URL、补缺口 | Top-k 不是全站枚举 |

推荐流程：识别站点 → 有界发现清单 → 按版本/语言/目录过滤 → 用户确认集合范围 → 逐页获取 → 固定修订 → 覆盖报告 → 全文索引。

## 3. AI SDK 的范围建议

对确认长期学习的核心 `/docs/` 集合，在选定范围内自动收录。Provider 文档先发现目录、优先获取实际使用部分；Cookbook 根据当前课题选择。用户需要完整参考归档时可以将后两者也纳入，但仍需批量范围授权和资源限额。

不同版本、语言和域名分别记录。外部链接不因被引用就自动扩大抓取范围；范围预览不能成为先偷偷抓完整站的理由。

本次对话没有完成全站归档，也没有得出可信的总页数。任何例子中的数量都不能当成 AI SDK 的实际页面统计。

## 4. 完整收录怎样定义

“全部”只表示这次明确范围与发现清单内的所有选中项。比较 sitemap、导航与内部链接发现差异；正文获取后检查空页、错误页、截断、版本选择和重要结构。HTML/Markdown 可能是同页面的表示，不重复计算为独立证据。

集合记录页面 URL、实际获取地址、版本线索、时间、正文 hash 和状态。逐页获取可能跨站点更新；冻结本地集合保证可重现，不自动证明源站原子版本一致。

返回成功、部分、失败、未知版本和排除项。已获取部分可支持局部查询，但不能回答超出覆盖范围的全量否定问题。

## 5. 学习研究怎样影响产品，而不是替产品背书

前次讨论没有找到或声称存在“自动爬 AI SDK 文档 vs 手动录入 Obsidian”的直接对照实验。以下是从学习研究向产品设计作的有限推论，不是该知识库已经有效的证据。

### 5.1 回忆与延迟表现

前次引用的文章学习实验比较重复阅读与回忆测试，强调即时熟悉感和延迟保留不完全相同。[L06] 因而系统不以已读页面数、收藏数或摘要浏览数认定掌握。

设计上可安排用户先解释一个机制、再对照原文纠错。这个启发不能直接证明闭卷测试对所有复杂编程任务始终优于示例学习。

### 5.2 间隔复习

前次引用间隔学习研究，讨论复习间隔应结合希望保留的时间尺度，而非一种时间表适用所有人。[L07]

“隔天、约一周、约三周”仅可作为试点参数，后续根据表现调整；不称通用最优。复习优先检查能力或误区，不机械推送同一篇长摘要。

### 5.3 自我解释和笔记

前次讨论引用自我解释研究，同时明确任务、对照条件与结果指标会影响效果，不能把“写了一段自己的话”自动计作掌握。[L08]

建议围绕问题解释机制、条件、例外，并用原文或实验检查。聊天中还提及一项较新的事实学习对照结果，但未保留足够完整的论文身份；此处不补造作者、标题、DOI 或量化结论，也不将其作为新的独立证据。

### 5.4 陌生知识先有示例

前次引用问题解决研究提醒：文章记忆中的测试效应不能机械外推到所有技能学习。[L09] 对陌生知识建议先提供完整例子，再补全、改变条件、独立迁移；不要求所有学习一开始都闭卷。

## 6. 四层自动化分工

| 环节 | 系统做什么 | 人保留什么 |
|---|---|---|
| 收集 | 发现、获取、去重、版本、基础索引 | 确认范围、选材价值与外发权限 |
| 组织 | 根据目标提出单元、必要资料和练习 | 调整目标与顺序，跳过已熟悉内容 |
| 理解 | 提供必要示例、分层提示与反馈 | 尝试解释、应用、判断条件和纠错 |
| 整理 | 将已表达内容组织成笔记并连原文 | 核对模型没有替自己编造结论 |

默认全量获取/基础索引不等于全量 embedding、全量编译或为每页创建 Todo。深度处理集中于当前课题；研究可查未读资料，但不能据此给用户标记学习完成。

## 7. AI SDK 目标驱动学习单元示例

以下是产品设计样例，不是官方完整课程、当前 API 兼容说明或用户已创建的计划。

| 单元 | 主要问题 | 可观察产出 |
|---|---|---|
| 模型调用与结果 | 输入、输出、失败分别是什么 | 能解释一次数据流 |
| 工具与执行循环 | 请求、执行、回传和继续如何连接 | 最小工具调用观察记录 |
| 控制与边界 | 停止、异常和副作用如何限制 | 改变条件后仍能解释行为 |
| 状态与恢复 | 哪些信息必须保存 | 状态说明与验证记录 |
| 项目集成 | 如何接入服务、界面、日志 | 一个小型集成任务 |

一次单元流程：定位必要材料 → 看解释和完整示例 → 收起原文尝试解释 → 分层提示和纠错 → 变式实验 → 保存适用范围、结果和未解决问题 → 按需复习。

实验执行独立授权；正在学习不等于可以自动运行导入仓库。

## 8. 三条状态不可混为一谈

资料状态记录发现、下载、解析、索引与缺口。知识状态记录主张、证据、审核与待复审。个人学习状态记录目标、来源版本、尝试、提示和应用结果。

任务系统加入后，还要单独显示执行状态和用时。计时结束不等于实验通过；报告生成不等于个人理解。避免只有 `mastered: true` 一个永恒布尔值。

文档更新时查依赖影响，保留历史正确尝试；只有需要新版本能力的目标进入补学候选，不重置整个学习记录。

## 9. 什么情境采用什么收录策略

| 情境 | 推荐策略 |
|---|---|
| 长期学习、索引清楚的官方文档 | 自动收录批准范围，按课题展开学习 |
| 巨大跨产品多版本文档站 | 广泛发现目录，优先收录目标产品/版本，按缺口补采 |
| 偶然遇到的博客 | 手动选材、自动入库，不自动爬整个作者站 |
| 登录/内部/敏感材料 | 人工选择并授权，不扩大访问和外发范围 |
| 一次性具体问题 | 定向取证，不要求先归档全站 |

保留选材与思考，消除重复复制粘贴。目录是否已收齐和用户是否已学会始终分开。
