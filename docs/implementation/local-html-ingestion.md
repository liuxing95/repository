# 本地 HTML 收录与接手

这项能力是场景 02“多来源收录”的一个入口，适合已经保存到本机的单份 `.html` 或 `.htm` 文档。它保存文件的原始字节，再提取静态正文供检索与固定原文回读。收录完成只表示这份来源可追溯、可检索；页面陈述仍是**未审核资料**，不会自动成为 Wiki 结论。

## 从文件到可检索来源

```mermaid
flowchart LR
  H[明确选定的本地 HTML] --> P[预览并冻结原字节]
  P --> B[(SQLite 原件与修订)]
  B --> X[macOS 隔离进程提取静态正文]
  X --> R[核对正文与覆盖缺口]
  R --> A[逐文件批准]
  A --> W[Obsidian 插件写入 KB-Sources]
  W --> C[回执齐全后提交来源]
  C --> S[本地索引、搜索与固定回读]
```

先按[开发者接手指南](../development/onboarding.md#2-从零运行一个独立试点)构建并连接一个独立试点，确保当前设备已登记为主端。进入插件设置的 **05 / 资料收录**，选择“本地 HTML 文件”，在入口中填一份 `.html`／`.htm` 文件的绝对路径。文件必须位于应用数据和试点 Vault 之外；这一入口不接受目录、ZIP、URL 或手工剪藏。剪藏片段请改选“文本 / Markdown / 剪藏”。可填写集合、语言和版本，默认编码为 UTF-8。

点击“预览获取范围”，确认只有预期的一份文件，再点击“确认清单并解析”。刷新本批后，打开“查看文字与定位”，核对章节、正文、表格和覆盖说明。确认内容可用，再点“审核正式导入文件”，展开将写入的 Markdown，最后点“批准以上文件并写入”。在 `KB-Sources` 中看到文件、在“浏览正式来源”中看到解析记录，两者都成立才算完成。随后在 **06 / 证据检索与问答** 搜索一段独有文字，并用“回读固定原文”检查引用和相邻上下文。

解析只处理所选文件的静态 HTML：优先读取 `main` 或 `article`，否则读取 `body`；提取标题、段落、列表、代码和表格文字。脚本不会执行，外部链接、图片和嵌入不会自动获取或识别。出现 `MEDIA`、`LOCAL_HTML_STATIC` 覆盖说明是预期行为；检索命中和“整理本次原文证据”也不代表语义审核通过。更新原文件后请创建新预览，旧修订保持不变。

## 代码、数据与边界

| 关注点 | 入口 |
|---|---|
| 类型、界面和搜索筛选 | [收录合同](../../packages/contracts/src/ingestion.ts)、[收录界面](../../apps/obsidian-plugin/src/views/ingestion.ts)、[搜索界面](../../apps/obsidian-plugin/src/views/search.ts) |
| 本地文件授权、冻结与解析调度 | [清单服务](../../apps/service/src/ingestion/manifest.ts)、[文件读取](../../apps/service/src/ingestion/file-reader.ts) |
| 隔离进程与静态提取 | [解析调度](../../apps/service/src/ingestion/parser.ts)、[进程入口](../../apps/service/src/ingestion/parser-entry.ts)、[HTML 解析器](../../apps/service/src/ingestion/web-parser.ts) |
| 审批、写入与回执 | [提交协议](../../apps/service/src/ingestion/commit.ts)、[插件 Writer](../../apps/obsidian-plugin/src/writer/apply.ts) |

原始 HTML 作为 BLOB 与哈希保存在应用数据目录的 `state.db`；来源修订和解析块也在该账本。`KB-Sources/<parseId>.md` 是经过批准的不可变文字投影，不能代替原始字节或数据库备份。整个流程留在本机，不需要模型密钥或 Docker。解析器只在已验证的 macOS 隔离环境开放，单次限 20 秒、V8 堆 256 MiB、结果 8 MB；系统总驻留内存可能高于 V8 堆。大文件即使低于 20 MB 原件上限，也可能因结构复杂而返回 `PARSE_FAILED`。

遇到 `PARSE_FAILED`，先查看本批是否保留原件，再核对文件编码和结构；可从“重新解析原件”选编码重试。仍失败时不要批准空内容或放宽隔离，保留原件与批次供排查。若看到已解析但没有正式来源，应返回“审核正式导入文件”核对批准、目标文件冲突和回执。检索未命中时先确认正式来源已提交、索引已完成，并取消不匹配的版本、集合或来源类型筛选。重启服务需要沿用同一应用数据目录；插件重启后须重新配对。

## 验证这项改动

```sh
pnpm check
pnpm exec vitest run tests/integration/ingestion-manifest.test.ts
```

集成用例检查了原 HTML 字节留存、静态正文提取、脚本与样式不进入正文，以及错误扩展名被拒绝。

2026-09-24 的独立试点中，一份用户提供的 1,155,259 字节 HTML 经真实 Obsidian 完成预览、解析、批准和写入。数据库保存的原件哈希与输入文件一致；解析得到 262,654 个字符、2,908 个定位块；`KB-Sources` 文件哈希与批准版本一致，正式来源数为 1。搜索“状态恢复”命中该来源，固定原文回读和本地原文整理均取得对应片段。`pnpm check` 同日通过：197 个常规测试、2 个编译产物测试，8 个环境专项默认跳过。试点原件与应用数据没有写进仓库，也没有上传；这些检查不替代人工语义审核。
